# 同一站点的检索留在 searxng，取件放进网关

知网这类站点，其**检索**作为 searxng 引擎接入（代码在 `searxng-ext/`），其**取件**作为网关的取件插件（代码在 `src/fetch/plugins/`）——同一站点的代码被拆到两处。判据是**聚合 vs 逐条**：检索产出多候选、需跨源去重与排序，一旦网关能识别它就得引入 provider 抽象（`docs/adr/0006` 已否）；取件是一个 URL 进、一个资源出、不参与聚合，放在网关内不构成上游抽象。

## Considered Options

- **检索也提到网关（provider 化）**：能统一"检索 + 取件"，但要重开 ADR-0006 否掉的 provider 抽象与跨源排序；被否。
- **取件也做成 searxng 引擎**：searxng 引擎只返回结果列表、不产出文件，且取件需要会话与落盘；被否。

## Consequences

- 同一站点会有两份代码，读者若不看本 ADR 会以为可以"顺手统一"——不要统一。
- 网关可以知道"取件"要用哪个插件，但仍**不知道**某条检索结果来自哪个引擎。
